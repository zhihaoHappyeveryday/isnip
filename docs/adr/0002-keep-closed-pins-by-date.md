# 按关闭日期保存贴图历史并跨启动恢复

会话缓存随 iSnip 退出清理，适合本次运行内的恢复。为支持跨天恢复，默认贴图历史目录沿用 `截图保存目录/iSnip Pin History`，自定义时直接使用用户选中的目录。iSnip 在贴图历史目录内按本地关闭日期自动创建 `YYYY-MM-DD` 子目录，同一天的 PNG 和文字贴图原文直接放在里面。

把关闭顺序、文件路径和显示状态记在配置目录的一份持久清单里。启动时读取清单，恢复一条时再读取对应的图和原文。这让 `ClosedPinHistory` 可以沿用统一的关闭和恢复入口，在多个日期与存储位置之间按关闭顺序工作。

## Consequences

- 正常退出时，桌面上仍显示的贴图按「关闭全部」的顺序记在退出当天，等本次写入完成后退出。意外结束后，已保存的记录可继续恢复。升级前的会话缓存沿用原有清理方式。
- 所有日期合计应用「可恢复贴图数」，默认 20 张，最多 50 张。超限时淘汰最早关闭的记录，设为 0 时清空历史。
- `F3` 按剪贴板的复制标识选择贴新内容或恢复历史。参见 [F3 关闭后优先恢复](#f3-关闭后优先恢复)。
- 成功恢复会取走一条历史，再次关闭时按新的关闭日期记入。恢复或淘汰时清理该记录自己的文件。
- 修改目录后，新增记录进入新位置，旧记录继续从原路径恢复。旧目录暂时离线时，`F3` 跳过并保留对应记录，接回后仍可恢复。

## F3 关闭后优先恢复

先复制文字，再从截图界面贴出并关闭一张截图时，0.4.0 的 `F3` 会优先贴出那段文字。调整后，贴图进入历史时剪贴板里已有的那次复制视为已处理。之后再复制的图片或文字可以优先贴出，主动重新复制相同内容也算一次新复制。复制标识只用于判断贴图顺序，剪贴板内容可照常粘贴。

`PinManager` 在收录前取得剪贴板复制标识，`ClosedPinHistory` 返回本次收录是否成功。历史接收时，`AirSnipAppController` 保存这个标识，沿用成功贴出剪贴板内容时用的记录和文件格式。`F3` 和菜单「贴图或恢复」继续走 `triggerPinOrRestore`。单张关闭、「关闭全部」和正常退出收录的贴图都从同一处记录。

复制标识文件无法写入时，本次运行仍按关图顺序处理。重开时使用磁盘上最后一次成功保存的标识，已收录的贴图仍可恢复。

### 验收用例

| 操作 | 期望结果 |
| --- | --- |
| 先复制文字，再从截图界面贴出截图并关闭 | 第一次 `F3` 恢复截图。历史用完后结束，主动再复制才能贴那段文字。 |
| 先复制图片，再依次关闭 A、B，历史只有这两张 | 连按两次 `F3` 恢复 B、A。第三次按键时恢复结束。 |
| 关闭后复制新图片，或重新复制相同的文字 | 第一次 `F3` 贴出新复制的内容，接着按 `F3` 恢复历史。 |
| 关闭前复制的图片在关闭后被 iSnip 后台压缩写回 | 后台写回沿用同一次复制，`F3` 先恢复。 |
| 复制后使用「关闭全部」，或正常退出并由 iSnip 收录仍显示的贴图 | 从最近关闭的一张开始逐张恢复，重开后也按此顺序。 |
| 先复制文字，`F3` 因同屏上限没贴出来，再关一张图 | 下次 `F3` 恢复刚关掉的图。想贴那段文字时重新复制。 |
| 复制新文字后，在历史设为 0 或收录失败时关闭一张截图 | `F3` 仍可贴出这次复制的文字。 |
| 关闭后已进入历史，后来后台写盘失败 | 提示写入失败，关图时的那次复制仍视为已处理。 |

先在 `feat/restore-closed-pins-from-disk` 通过贴图冒烟测试，再将修复合入本地 `feat/isnip-integrated`，复验同一组用例。
