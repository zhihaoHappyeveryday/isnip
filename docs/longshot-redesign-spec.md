# iSnip 页面长截图重设计规格

**讨论记录截至 2026-11-22。** 本文记录页面长截图的设计、实测证据，以及新一轮自动恢复的验收规则。

**重设计起点**　上一轮从 `v1.0.3`（`8fc34d6`）恢复两个长截图入口、滚动、拼接和专用测试，再实施重设计。回滚时 73 项 Swift 测试和应用自检通过。 [v1.0.3 发布记录](https://github.com/zhihaoHappyeveryday/isnip/releases/tag/v1.0.3)

**本轮对照**　自动恢复优化以已发布的 `v1.0.7`（`a0d54ff`）为基线。从安装版的两个入口验收，并检查导出的成图。 [v1.0.7 发布记录](https://github.com/zhihaoHappyeveryday/isnip/releases/tag/v1.0.7)

## Problem Statement

用户需要从网页或原生软件截取一段比屏幕更长的内容。此前遇到过页面在滚动，成图只有首屏，或起步提示无法确认、反复点「自动翻页」仍然接不上的情况。小选框里含固定栏时，问题更容易出现。用户希望操作简单，框选后就能让软件自己截完。

上一轮隔离测试通过后，实际安装版的两个入口仍能复现 PDF 首段拼接失败。后续的验收需要覆盖真实桌面环境，从实际操作入口启动，并检查最终成图的内容。

`v1.0.7` 在 B 站宽矮选框上已经拍到了连续内容，却因评论框悬停变色而中断。用户希望视频、浮层、空白和重复列表等内容沿用一个自动流程。软件应核对实际位移和已拍范围，优先接着截，必要时从原选区起点重截一次。

## Solution

**把一次完整出图的成功率放在首位。** 用户从菜单栏「页面长截图」框选并松开鼠标，或者先做普通截图、框选后点击工具栏的长截图按钮。自动模式沿着用户选中的滚动区域截到可确认的末尾，过程中自动处理取图时机、步长和能确认的续接。用户可以按空格提前暂停，并复制或保存已确认的部分。

成图从原选区对应的首屏起步，保持选区宽度与像素比例，连续覆盖到可确认的末尾或高度上限。接不上时先原地补抓，再回退续接。仍接不上且能找回原选区起点时，提示并自动从头重截一次。重试用完后，保留当前一轮已经连续截到的部分，明确显示中断。

## User Stories

1. 作为从菜单栏发起长截图的用户，我希望点「页面长截图」并松开选框后自动开始，以便一次操作截完。
2. 作为从普通截图开始的用户，我希望框选后点工具栏上的长截图按钮就能自动开始，以便沿用熟悉的入口。
3. 作为截取网页正文的用户，我希望长图从我框到的位置开始，以便第一屏也出现在结果里。
4. 作为只需要一栏内容的用户，我希望长图沿用选区的宽度，以便成图只包含我要的范围。
5. 作为截取整段网页的用户，我希望软件自动滚到正文末尾，以便获得最后一段内容。
6. 作为使用 Chrome 或 Safari 的用户，我希望在常见网页上一次框选即可完成，以便在不同浏览器里使用相同流程。
7. 作为使用 MarkEdit 的用户，我希望截到文档的最后一行，以便分享完整内容。
8. 作为在「预览」里看 PDF 的用户，我希望跨页处能连续接上，以便成图里页与页之间没有缺行或重行。
9. 作为只框几行正文的用户，我希望软件按实际可滚动的内容控制步长，以便小框也能接上。
10. 作为截取带固定顶栏或底栏页面的用户，我希望正文顺序连续，以便固定栏不会造成重复的内容。
11. 作为截取带独立侧栏页面的用户，我希望实际滚动的是选中的正文，以便得到我想要的区域。
12. 作为浏览含空白或重复条目的用户，我希望软件核对实际的滚动进度，以便成图不会漏掉看起来相似的段落。
13. 作为浏览加载较慢网页的用户，我希望自动翻页等待画面可用，以便刚加载出来的内容能接上。
14. 作为使用有悬浮指针或浮动控件的桌面用户，我希望软件能处理画面干扰，以便正常滚动时仍能生成完整长图。
15. 作为在自动翻页时把鼠标移出选框的用户，我希望软件继续把滚动发给原目标，以便无需摆正鼠标才能截完。
16. 作为在意完整性的用户，我希望软件先小步确认再继续，以便提高一次成功率。
17. 作为遇到短暂失配的用户，我希望软件自己补抓和调整步长，以便少一次手动找接缝的操作。
18. 作为只需要页面前半段的用户，我希望按空格暂停并保留已确认的部分，以便马上复制或保存。
19. 作为需要暂停或结束长截图的用户，我希望可以随时停止自动滚动，以便恢复对鼠标和页面的正常操作。
20. 作为主动选择手动滚动的用户，我希望仍能用鼠标或触控板控制进度，以便截取自己需要的片段。
21. 作为截到高度上限的用户，我希望看到具体的停止原因并保留已有结果，以便知道这次截到了哪里。
22. 作为遇到持续中断的用户，我希望得到已经接好的连续部分和清楚的状态，以便决定是否重新框选。
23. 作为要分享长图的用户，我希望照常复制和保存结果，以便继续现有工作流程。
24. 作为准备验收新构建的用户，我希望测试从 Mac 上实际安装的应用开始，以便确认自己会用到的两个入口。
25. 作为负责选型的维护者，我希望用同一批失败素材比较现成实现，以便复用确实能提高成图成功率的方案。
26. 作为后续接手的工程师，我希望知道哪些做法已确认、哪些只有回放证据，以便延续现有判断。
27. 作为截取动态网页的用户，我希望软件能依据稳定正文确认接缝，以便悬停变色或动效出现时继续截完。
28. 作为遇到拼接中断的用户，我希望软件先试着接回已截内容，接不回时提示并自动从头重截一次，以便继续完成长图。
29. 作为从文档中段开始的用户，我希望从头重截仍从我最初框选的位置开始，以便成图包含我选择的第一段内容。
30. 作为正在从头重截的用户，我希望预览显示新一轮的进度，并能照常暂停或取消，以便随时决定截到哪里。
31. 作为遇到再次中断的用户，我希望软件结束自动重试并保留当前结果，以便保存已截的部分或自行重新框选。

## Implementation Decisions

### 已确认的原则

- 成功率优先。成功指自动模式从用户开始的选区截到可确认的末尾，结果连续且准确。方案正确率接近时，再比较速度和维护成本。
- 两个入口共用现有长截图会话。会话负责同一目标的取帧、滚动、确认接缝和停止，再把结果交给现有复制、保存或标注流程。手动滚动是用户可以主动选择的模式。
- 保留现有的 Swift、AppKit、ScreenCaptureKit 和 macOS 14 最低支持版本。优先采用经对照验证有效的系统能力、项目代码或开源实现。需要自写的部分以已有方案确实无法覆盖、且有清楚的失败样本为前提。
- 把目标窗口、滚动区域和原选区关联起来。每一步先确认目标实际滚动了多少，再确认可见内容有重叠。用于判断位移的画面可以覆盖同一个滚动区域里的更多正文，出图仍按用户选的范围和已确认的出图规则。
- 用实际可滚动正文高度决定步长。画面未稳定就原地补抓，发现步长太大就减小后续步长。需要回到重叠位置时，以已确认的位置为依据。区分已到末尾、暂时未动、无法拼接、用户暂停和达到上限。
- 固定栏和局部动效要与真正滚动的正文分开判断。用稳定正文估计位移，再核对原选区的接缝。匹配时忽略某个区域和最终成图如何呈现它是两个决定。

### 每步拉回鼠标的采用条件

- `v1.0.3` 在自动翻页开始时按需移动真实鼠标，初次画面未变化时还会再次检查。默认滚轮作用点是选框横向正中、距顶部约 46% 的位置。每次发出的滚轮本来就带有这一固定坐标。
- 用户允许为提高成功率牺牲自动滚动期间的鼠标自由。如果实测鼠标移出选框会造成停滚或滚错，且每步拉回能增加完整出图次数，则在每次自动滚动前强制把真实鼠标移回已确认可滚动的点，再发滚轮。中心可作为首选，落在固定栏或独立侧栏时改用目标正文里能滚动的点。用户暂停或截图结束后停止移动鼠标。
- 真机对照只更换鼠标拉回方式，沿用同一个窗口、选框、起点和滚轮坐标，在同一阶段把鼠标移到框外。两种方式各完成 4 次完整长截图，采用现有的固定滚轮坐标。

### 已确认的成图规则

- 框上叠着其他 App 的浮层时，只截目标窗口在原框里的内容。
- 选框内的固定顶栏、底栏和侧栏各保留一份。顶栏在开头，底栏在末尾，侧栏仅保留首屏内容。匹配时将固定内容与滚动正文分开。
- 有明确末尾的滚动区域按完整出图验收。没有明确页尾时，持续接上可验证的内容，达到设置的上限后保留结果并显示「已达高度上限」。

### 自动恢复与从头重截

1. **原地补抓。** 接不上时先停发滚动，短时补抓。用同一滚动区域里能唯一对齐的稳定内容核对位移，遇到重复画面时用可验证的实际位移消除歧义。固定栏和局部变化可以跳过对齐判断，出图仍按原选区取材。只有确认选区内的连续覆盖后，才追加新内容。正常能接上的步骤直接继续。
2. **回退续接。** 补抓后仍接不上时，尝试回到最后确认的位置，重拍并核对接缝。确认接回后减小步长再向下滚动。回到更早的已确认位置时，经过的旧内容只保留一份，到已有长图的末端之后才追加。同一轮里，只有拼入新的内容才会刷新补抓和回退的重试次数。用完次数仍接不上时，进入从头重截的判断。
3. **从头重截。** 首次框选时记住选区、目标滚动区域和原选区起点。回到同一目标后限时补抓，确认新取的首屏对应原选区起点。回到起点附近且画面能确认还差多少时，按测得的距离再校正一次。确认起点可用时，显示「正在从头重截」，清空已拼内容和进度，用同一个框开始自动翻页。原来从页面中段开始，就回到原来那一段。重截沿用第一轮已经减小的步长。如果第一轮还没缩步，就按现有规则减小步长再启动。首屏依靠能定位的内容确认，允许局部动效继续播放。
4. **结束重试。** 一次用户框选最多自动重截一次。重截前扣掉这次机会，清空拼接进度和点「继续」都沿用剩余次数。找不到原选区起点，或用完重截机会后仍无法续接时，结束自动翻页并提示「长截图未完成，已保留结果」。用户仍可复制或保存当前一轮的连续部分。用户重新框选时开始一次新操作。

暂停或取消在恢复期间同样生效。点「继续」时先核对当前画面，从原选区起点或其他已确认的位置接回。位置未确认时提示重新框选。进入自动从头重截前，先应用页尾收尾规则。达到高度上限时显示「已达高度上限」。

### 页尾收尾

1. **确认实际页尾。** 核对原选框对应的滚动区域是否到了末尾，画面短暂停住只作为线索。无法确认页尾时，沿用常规恢复和重试上限。补尾期间若同一滚动区域加载出新内容，恢复正常翻页并在新的末尾重新判断。
2. **已拼全就完成。** 同一滚动区域已到底，且已确认的长图连续覆盖到最后一行时，用已确认的画面收尾，停止滚动和重试，显示「已到末尾」。此后的页尾动效保持已完成状态。
3. **仍缺内容就补尾。** 确认到底后末屏还没接上，先在原地限时补抓，再回到最近确认的位置小步补齐，沿用现有补抓和回退上限。回退后仍按这次页尾收尾处理。用完补尾次数仍接不上时，停止滚动，提示「末尾未接上，已保留结果」，让用户复制或保存当前长图。从头重截由用户主动重新框选发起。

## Testing Decisions

- **主要验收入口是实际安装版的用户流程。** 在用户 Mac 上核对正在运行的安装路径和构建校验值，确认屏幕录制与辅助功能权限已生效。在菜单栏点「页面长截图」并真实拖框，在普通截图中拖同样的框再点工具栏按钮。两条路径都观察最终复制或保存的图像。每次试验结束后，把网页或文档恢复到顶部。
- **每个验收场景用多组随机选框。** 两个入口的正常长截、回退续截和从头重截都按此验证。按宽矮框、窄高框、只框几行正文的小框和常规框分组，在场景允许的范围内随机选取选框的像素坐标、宽度和高度。页面起点覆盖页首和中段。Retina 上覆盖奇数和偶数像素边界。
- **对照使用同一批随机选框。** 新旧版本或方案逐个对照，保持同一个窗口、实际选框、页面起点和滚动速度设置。覆盖用户提供的网页、Chrome 和 Safari 的普通正文、MarkEdit 编号文档和「预览」里的编号 PDF。记录实际选框的像素坐标、宽高、页面起点和屏幕缩放比例，自动抽样时还记录随机种子。统计完整成功次数和试验总数，以及失败发生在起步、滚动、接缝还是收尾。
- **成图是判断依据。** 编号素材从选框首行逐行核对到末行，确认每行按顺序出现一次。可建立准确参考图时，核对尺寸和像素连续性。一起记录真实滚动末尾、首段接上时间、自动完成时间和停止原因，核对过的内容决定成功率。
- **覆盖这次讨论的反例。** 同一批样本包含小框配固定栏、独立侧栏、空白或重复正文、延迟加载、桌面远程指针和窗口内浮层。测试移出鼠标仍能滚对目标，按空格可提前停止并输出连续部分，持续失配或达到上限会显示正确状态。核对 Retina 与非 Retina 的选框和成图比例，并覆盖所用 Mac 的多屏和全屏场景。
- **回放和单元测试补充定位。** 用取自同一滚动动作的两组帧对照采集来源。用相同帧测试拼接模块输出的图像和位移。沿用现有长截图的固定顶底栏、固定侧栏、滚动方向、延迟渲染和重复内容测试，加上应用冒烟自检。生产验收沿用两个入口，程序回放的通过记录保留在诊断证据中。
- **取帧以像素对齐为准。** 选框边缘可以落在任意屏幕像素。取帧遵循系统的整数点坐标，成图再按原选框的像素边界裁切。
- **真人操作纳入验收。** 从两个入口分别慢拖、反向拖和框选几行正文。覆盖 Retina 上奇数像素宽高、放开鼠标后移出选框、远程鼠标移动、滚动中按空格暂停，以及回到页首后点继续。核对滚动目标、接缝、成图宽度和停止原因。真人发现中断时，记录该次选框和前后帧，用同一组输入做修复前后的对照。
- **验收包可辨认。** 本轮安装包使用 `v1.0.8-bate-N` 命名，每轮编号递增。「关于」页显示同一个构建编号，真机验证时核对安装位置与程序校验值。
- **局部变化可以接回。** 用 B 站失败帧回放核对实际位移，再在安装版把鼠标停在原来的位置，按真人慢拖框选并滚过评论框。检查成图是否继续覆盖到页尾。编号样本用来检查固定栏、空白和重复正文是否造成漏段或重段。
- **回退能补齐缺口。** 让小选区的一步滚动失去重叠，检查自动回到已确认的位置并用较小步长接回。核对结果的行序和高度。正常页面用 `v1.0.7` 对照完成时间。
- **重截按新一轮出图。** 从编号文档中段框选，触发补抓和回退都无法接续的情况。覆盖第一轮已经缩步和还没缩步两种情况，核对一次提示、找回原选区起点，以及按较小步长连续截到末尾。预览和导出都应采用新一轮的内容。用同一组失败素材对照常规步长重截与缩步重截，记录完整出图次数与耗时。另测含持续局部动效的首屏可以在确认起点后开始重截。
- **两轮都失败时确实停止。** 让第一次翻页和从头重截都遇到持续失配。核对只重截一次，第二次补抓和回退失败后显示最终提示，滚动停止，复制和保存只包含当前一轮已确认的内容。另测找不回原选区起点时保留当时的图，以及在恢复期间暂停、取消和继续均遵守一次重截的上限。
- **大框到页尾时核对成图。** 用同一个大框截 100 行编号内容。第 100 行已拼入后使页尾局部闪动，成图应完整且按顺序保留每行一次，并显示「已到末尾」。另让页面滚到底时只拼到第 98 行，核对先尝试补齐最后两行。若末屏始终接不上，应提示「末尾未接上，已保留结果」，导出完整的前 98 行。以上页尾用例的自动从头重截次数均为零。

## Out of Scope

- 改造普通截图、标注、OCR、贴图和现有导出格式的其他行为。
- 整体迁移另一款截图软件的界面、设置和发布流程。
- 新增浏览器扩展或其他操作系统支持。
- 在当前讨论记录中决定最终采用哪个拼接库、移植哪些代码或改动发布版本。

### 术语

- **长截图首屏**是原选区对应的第一个可确认画面。
- **滚动区域**是窗口内会独立滚动的内容，例如正文、文档视图或侧栏。
- **自动翻页**是软件持续滚动同一目标并逐步拼接的过程。
- **接缝**是前后帧重叠并可确认连续的位置。
- **目标窗口取帧**是从选中窗口取得图像。它需要符合成图规则，并校验窗口、选框和显示器像素坐标。
- 原选区起点和从头重截的定义见[项目术语表](../GLOSSARY.md)。
