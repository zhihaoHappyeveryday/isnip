# 长截图拼接中断修复设计

本文记录 v1.0.6 的行为。后续已确认的优化见 [长截图起步与续接设计](longshot-reliability.md)。

## 问题

长截图靠相邻两次截图里的共同内容判断接缝。滚动后如果没抓到画面，或者两张图已经没有足够的重叠，就无法知道中间漏了什么。v1.0.3 遇到抓屏没有结果时会进入下一轮滚动。对不上时会原地补抓一次，再减小后续步长。页面可能继续往下走，预览却停在上一段。点击完成时，最后一次抓屏或拼接失败也会输出已有图像，可能只有首屏。

v1.0.3 在 Chrome 彩色测试页上滚动了 1,800 CSS px，暂停后得到的图是 1569 × 2590，完整的测试行到第 025 行。当时页面已滚到约第 035 行。这个实测确认了少拼后半段，首次丢帧或对不上的原因仍未定位。用现有拼接代码回放高度为 120 px 的画面时，按 0、70、140 px 采样可以拼出 260 px。跳过 70 px 处的画面后，首尾接不上，结果停在 120 px。

v1.0.5 用框选时的冻结画面作为首屏。第一次自动滚动前，暂时抓不到实时画面或画面对不上，就可能在一格滚轮都没发出的情况下提示「拼接中断，请往回滚一点」。用现有代码回放时，直接用实时画面替换首屏会产生另一种错误。切换页面后可以拼出完整的另一页，提前滚动后可以拼成功但漏掉开头。

## 起步与首屏

1. 框选确定选区，框选时的画面提供预览和初始起点。框选裁切和实时抓图使用同一个对齐到像素的选区。尺寸不符的抓图视为不可用。实时画面能确认仍在原处时，用它刷新首屏。画面已经移动但仍有可信重叠时，接上新增内容，保住原来的开头。两种情况都可以自动继续。
2. 框选层退出后尽快开始抓图。暂时抓不到或接不上时，在原地补抓，整轮最多尝试 5 次，包含首次抓取。前一次失败后依次等 300、500、700、900 毫秒再抓，整轮从首次抓取开始最多 3 秒，抓取本身也计入。接上立即继续，次数或时间先到上限就暂停。超时、暂停或结束后返回的旧结果不能触发滚动。
3. 起步准备超限，或首次滚动后用完恢复机会，而且这一轮从未拼进过新内容时，可以保留选区，用最近抓到的有效画面作为待确认的预览。点「自动翻页」才确认新的首屏。继续前检查当前画面能否与预览接上，接不上时更新预览并等待确认。已有长截图进度时，继续从最后确认的位置尝试接回。

## 滚动与恢复

1. 自动滚动一步后，等页面绘制并抓屏。确认新画面有足够重叠、把新内容拼进去后，再继续向下滚。步长以实际可滚动区域为准，已识别的固定页眉、页脚要扣除。小选区也要保留重叠。
2. 暂时抓不到画面、画面看起来没动，或新画面对不上时，先在当前位置限次补抓。画面相同只能说明没有识别到新内容。能够确认仍在已拼位置时可停滚，工具条用「未检测到新内容」说明结果。
3. 已经发出向下滚轮，且原地补抓到的有效画面仍对不上时，尝试一轮向上回滚。每轮最多 3 小步，反向滚轮累计发送量不超过触发这次恢复的向下滚轮发送量。每退一步就抓图检查，以最后一次确认的画面为参考。接回后立即结束回滚，用较小的步长继续，只拼进新增内容。如果始终没拼入下一段，再次失配就暂停。
4. 回滚用完仍接不上，或一直拿不到可用画面时，停止自动滚动，保留选区、工具条和已经截到的内容。按空格可立即停止继续发送滚轮事件。已经发出的滚动稳定后，再检查当前位置。
5. 自动翻页开始或继续时，沿用现有的光标判定。光标在目标区域内的适合位置时留在原位，需要时移到选区中间附近，帮助滚轮事件落在目标区域。向上回滚使用同一类滚轮事件。 [现有光标与滚轮处理](../Sources/AirSnipApp/SystemServices.swift#L368)

## 暂停后的提示

| 情况 | 工具条提示 | 接下来怎么做 |
| --- | --- | --- |
| 起步补抓超限，始终没有可用的实时画面 | 未抓到画面，点「自动翻页」重试 | 保留选区和原预览，点按钮后再抓。 |
| 第一次滚动前有实时画面，补抓后仍接不上 | 无法确认起点，点「自动翻页」从这里开始 | 显示当前画面，点按钮确认从这张预览开始。 |
| 已滚动且恢复失败，这一轮从未拼成首段 | 首段未拼上，点「自动翻页」从当前画面重新开始 | 有可用画面时显示当前预览，由用户确认新起点。抓不到画面时提示点按钮补抓。 |
| 已经拼过长图，恢复后仍接不上 | 拼接中断，请手动滚到能接上的位置 | 保留长图预览，页面手动接回后再继续自动翻页。 |

## 暂停与输出

- 按空格暂停后，等刚发出的滚动稳定下来，再检查当前位置。能接上的新内容加进预览，工具条继续保留。
- 自动滚动时点复制、保存、另存为、标注或 OCR，先停滚并补抓最后一屏。已拼入至少一段内容且当前位置已确认接上时，才结束会话并输出。仍接不上时保留工具条和预览，可手动接回后再试。只有首屏时提示「尚未拼成长截图」。
- 确认下一段能接上，但整段加进去会超过高度上限时，停止滚动，在工具条的「宽 × 高」旁显示「已达上限」。已拼成的长图可直接输出，超限段留在图外。输出仍要求已经拼入至少一段内容。如果第一段已经超限，可手动往回一点，再试较短的一段。

## 实现位置

`LongshotSessionController` 负责滚动、抓屏、恢复和工具条状态。复用现有抓屏循环和共用的输出入口。先处理首屏准备与确认，再按顺序发送滚动、等待画面和拼接。失败时先解决当前滚动，暂停或输出请求切换后，较早的抓屏结果只能用于当前仍有效的检查。所有输出操作共用一次检查，通过后再关闭工具条。 [会话控制器](../Sources/AirSnipApp/LongshotOverlayController.swift#L32) · [共用输出入口](../Sources/AirSnipApp/LongshotOverlayController.swift#L665)

`LongshotCanvas` 负责验证重叠和写入图像。把回滚时的重叠检查做成只读，复用已有行匹配。只有验证通过且能接入的新像素才进入画布。匹配失败或超限时，已拼像素和最近一次可接续的参考一起保留。正常拼接每步取一帧。能同时用不同的滚动距离解释画面时，等新画面提供足够依据再接入。 [拼接入口](../Sources/AirSnipCore/LongshotEngine.swift#L1193) · [画布写入](../Sources/AirSnipCore/LongshotEngine.swift#L1330)

## 验收

| 场景 | 通过标准 |
| --- | --- |
| Chrome 彩色编号测试页 | 滚动后预览高度持续更新。按空格后，能接上的末屏进入结果。导出的行号连续，无漏行或重复。 |
| 首次抓屏为空，或页面重绘后恢复 | 原地按递增间隔补抓，接上立刻开始。等待期间没有滚轮事件。 |
| 首屏始终抓不到，或抓屏结果超时后才返回 | 先达到 5 次或 3 秒就暂停。工具条提示重试，迟到的结果不触发滚动。 |
| 首次实时画面切到了另一页 | 显示当前预览和继续指引。用户确认后才可从当前画面开始。如果确认时画面又变了，需要先看更新后的预览。 |
| 首次抓屏前页面已移动，仍有可信重叠 | 原来的开头仍在长图中，已出现的新内容只拼一次。 |
| 一步滚得太远 | 最多回滚 3 小步，反向发送量有上限。接回后用较小的步长继续，画布中的已截内容不重复。 |
| 首次滚动后恢复失败，这一轮从未拼成首段 | 工具条明确提示从当前位置重开。点「自动翻页」确认后才替换首屏。 |
| 已拼过内容后恢复失败，包括撤销到只剩首屏 | 停滚并保留已确认的起点和预览。提示手动接回，再继续这一轮。 |
| 正在滚动或回滚时按空格 | 停止发送滚动事件，检查当前位置，保留控制条与已拼图像。 |
| 正在滚动时点任一输出操作 | 先停滚并补抓。接上后才输出，否则保持这一轮并提示。 |
| 只有首屏，或仍有未解决的拼接中断 | 复制、保存、另存为、标注和 OCR 一致受限。 |
| 下一段能接上但超过高度上限 | 显示「已达上限」，现有长图的预览与导出一致，画布没有加入超限段。 |
| 小选区、固定页眉和相似内容 | 步长留出可用重叠。起步时相同像素可对应不同滚动位置，则先停下来让用户确认。 |
| 从选区外启动或继续 | 光标和滚轮事件沿用现有定位方式，目标区域继续可滚动。 |
