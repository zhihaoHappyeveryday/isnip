# iSnip 浮动提示改造设计

## 目标

浮动提示出现时，用户能一眼看清操作结果。遇到贴图上限等能明确处理的情况，第二行告诉用户下一步怎么做。采用已确认的「两行指引」预览，统一现有屏幕顶部的浮动提示。

## 外观和文案

提示在屏幕顶部居中，沿用现有屏幕选择方式。卡片跟随 iSnip 的浅色或深色外观，使用细边框和柔和阴影。两行卡片采用预览中的暖白和蓝灰背景。主标题、次行和右侧数量有清楚的层级，提醒图标放在浅琥珀色的小方块里。

| 场景 | 卡片样式 | 停留时间 |
| --- | --- | --- |
| 复制或保存成功 | 16 pt 的单行文字配对勾。参考高度 47 pt，圆角 12 pt。 | 约 1.5 秒 |
| 有明确下一步的提醒 | 18 pt 标题、14 pt 指引，左侧使用提醒图标。简短中文示例的参考尺寸为 322 × 77 pt，圆角 15 pt。 | 约 3 秒 |
| 其他状态和提醒 | 用同一套单行卡片呈现，图标表达信息或警告。 | 短状态约 1.5 秒。需要读清的警告和已有较长时长的通知约 3 秒。 |

「两行」指标题和处理办法两个层级。中文和英文按实际文本测量。文字较长或屏幕较窄时自然换行，卡片随内容增高，字号保持足够阅读。中英文文案沿用项目现有的本地化方式。

### 贴图数量上限

标题显示「贴图已达上限」，下一行统一写「关闭贴图，腾出位置后再试」。右上角用小字显示「当前已贴张数 / 设定上限」，例如 `4 / 4`。新贴和恢复贴图共用这一条提示。

把上限调低后，仍按实际数量展示。例如已有 7 张、上限 5 张，显示 `7 / 5`，使用同一句处理办法。贴图和恢复仍沿用原有操作流程。 [上限检查](../Sources/AirSnipApp/PinWindowController.swift#L140)

## 显示规则

- 同时展示一条浮动提示。相同内容再次触发时沿用正在显示的卡片，从最后一次触发重新计时。不同内容接替当前提示。
- 「操作完成提示」统一控制复制和保存成功的浮动提示，覆盖普通截图、长截图、贴图图片和原文、OCR 条码与取色等已有入口。关闭时，上限、权限或操作失败的提醒，以及切换边框、穿透、检查更新等状态提示，继续按各自的触发条件显示。设置说明相应改为「复制或保存完成后，在屏幕顶部短暂显示提示」。 [通用页设置](../Sources/AirSnipApp/SettingsWindowView.swift#L521)
- 提示浮在相关的应用界面前方，保持鼠标和键盘原有焦点。截图覆盖层内触发的提示也应可见。系统权限弹窗、OCR 和翻译结果、按钮原位反馈各自沿用现有形式。

## 重构落点

`ToastHUD` 统一维护卡片的排版、样式、计时和替换。调用方只传提示类型、标题和需要时的指引或右侧数量。正常确认用对勾，警告用醒目的提醒图标。发布、长截图和贴图历史仍由各自的业务代码决定发出什么提示。 [浮动提示实现](../Sources/AirSnipApp/ToastHUD.swift#L4)

贴图数量和上限由已有的上限检查传入。由各操作入口读取同一个「操作完成提示」设置，再决定是否发送复制或保存成功的浮动提示。相同类型、标题、指引和数量视为同一条提示。旧的结束计时和淡出动画只负责自己的卡片。

## 验收

| 场景 | 预期结果 |
| --- | --- |
| 达到上限后新贴或恢复一张 | 顶部居中显示两行卡片，包含实际数量和同一句处理办法。左侧是提醒图标。 |
| 已贴 7 张时把上限调到 5 张 | 再次触发贴图时显示 `7 / 5`，指引仍为「关闭贴图，腾出位置后再试」。 |
| 达到上限后连续按 F3 | 同一张卡片持续显示，最后一次触发约 3 秒后开始淡出。 |
| 上限提醒展示期间发生另一项操作 | 最新提示接替当前提示，旧提示的计时和动画不会提前关闭新提示。 |
| 打开或关闭「操作完成提示」 | 普通截图、长截图、贴图、OCR 条码和取色的复制或保存成功浮动提示一致跟随开关。上限、失败和手动状态提示仍按条件显示。 |
| 在截图覆盖层中触发提醒 | 提示可见，原来正在框选或操作的界面保有鼠标和键盘焦点。 |
| 浅色、深色、中文、英文与较窄屏幕 | 标题、指引、数量清晰可读，长文自然换行。短成功提示仍像预览一样紧凑。 |
